# Reusable scientific-harness convergence pattern

Use this pattern when a previously successful numerical claim must be restored or strengthened on a moving canonical codebase.

1. Reconcile the exact current parent implementation and frozen predecessor evidence.
2. Transplant frozen scientific code byte-for-byte when possible; adapt dependencies rather than silently retuning the experiment.
3. Add an orthogonal oracle when the production implementation and analytic target share a computational path.
4. Use negative controls with enough parameter separation to have actual discriminatory power.
5. If the proposed observable is regulator-sensitive, preserve that failure and replace the *candidate invariant* only when a mathematically better-defined quantity exists; never loosen a gate merely to recover PASS.
6. Prefer state-only or symmetry-protected quantities when they remove arbitrary operator normalization while retaining the physical obstruction under test.
7. Freeze thresholds before independent CI, record whether freezing occurred before or after exploratory runs, and distinguish engineering qualification from blinded scientific preregistration.
8. Require fail-closed scope fields so finite Type-I evidence cannot promote continuum factor type, geometry, or dynamics.
9. Re-run across independent runtimes, retain JSON artifacts and hashes, and merge only after both dedicated and repository-wide qualification pass.
10. Promote only the smallest next claim authorized by the evidence.

This pattern was extracted from the independent-BKM oracle repair, the current-main dS2 relational transplant, the regional modular-overlap transplant, and the cutoff-sensitive network-invariant repair.
