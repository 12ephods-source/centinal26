# Physical GA Campaign Protocol — v1.0.0-rc3

## Purpose

RC3 converts the remaining physical release gates into one resumable campaign. It does not weaken certification policy and does not create synthetic physical evidence.

Required GA evidence remains:

1. HOST_VALIDATION — signed distribution source evidence is not required because this is host-produced release evidence.
2. DISTRIBUTION_VALIDATION — generated by the installer for the actual installed payload.
3. ANDROID_VALIDATION — must be Ed25519-attested and must report Android + Termux + `physical_android_validated=true`.
4. ENDURANCE_VALIDATION — must be Ed25519-attested.
5. DEVICE_SYNC_VALIDATION — must be Ed25519-attested and must verify a signed bundle from a locally pinned peer key on a physical Android/Termux host.
6. Recovery drill and local integrity checks.

## Safety invariant

`automation-platform-ga run` refuses the physical campaign on a non-Android/Termux host. `--allow-host-smoke` is only an orchestration test mode; certification still remains REVIEW because the generated Android evidence cannot satisfy the physical flag.

## Phone A

```bash
automation-platform-ingest-canonical Automation
automation-platform federation-keygen "Phone-A"
automation-platform-ga --project Automation plan
automation-platform-ga --project Automation pairing-export --output ~/storage/shared/Download/phone-a-pairing.tar.gz
```

## Phone B

```bash
automation-platform-ingest-canonical Automation
automation-platform federation-keygen "Phone-B"
automation-platform-ga --project Automation pairing-export --output ~/storage/shared/Download/phone-b-pairing.tar.gz
```

Read Phone B's fingerprint directly on Phone B:

```bash
automation-platform federation-identity-v2
```

Transfer only the public pairing archive. On Phone A, compare the displayed fingerprint with the independently observed Phone B fingerprint, then explicitly confirm it:

```bash
automation-platform-ga --project Automation pairing-import \
  ~/storage/shared/Download/phone-b-pairing.tar.gz \
  --expected-fingerprint '<PHONE_B_FINGERPRINT>'
```

No private key is included in a pairing package.

## Signed federation bundle from Phone B

```bash
automation-platform federation-capture Automation
automation-platform federation-export-signed Automation \
  --output ~/storage/shared/Download/phone-b-signed.tar.gz
```

Transfer that signed bundle to Phone A.

## Run the campaign on Phone A

Default endurance: 60 cycles × 60 seconds = approximately one hour.

```bash
automation-platform-ga --project Automation --release 1.0.0-rc3-ga-campaign run \
  --node-name "Phone-A" \
  --peer-bundle ~/storage/shared/Download/phone-b-signed.tar.gz \
  --endurance-cycles 60 \
  --endurance-interval 60
```

Campaign state is written under:

```text
~/automation-platform/validation/ga-campaign-*/GA_CAMPAIGN.json
```

If the session is interrupted, rerun with the emitted campaign directory:

```bash
automation-platform-ga --project Automation --release 1.0.0-rc3-ga-campaign run \
  --campaign-dir ~/automation-platform/validation/ga-campaign-<ID> \
  --peer-bundle ~/storage/shared/Download/phone-b-signed.tar.gz
```

Completed gates are reused unless `--force` is supplied.

## Inspect status

```bash
automation-platform-ga --project Automation --release 1.0.0-rc3-ga-campaign status
```

A final PASS requires all required evidence, valid attestations, a current recovery drill, SQLite integrity, foreign-key integrity, audit chain, snapshot chains, and certificate chain.
